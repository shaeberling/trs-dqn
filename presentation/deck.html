01 / The learning contractNo expert actions. No hidden-state policy.

Screen in. Actions out. Score is the reward.

The agent discovers useful behavior by playing—not by being told where the ball will go.

No action oracle

  • No ball coordinates, trajectory solver or paddle tracker
  • No scripted steering, forced serve or human play data

Tooling can read the visible HUD

Score differences provide reward. Visible lives and GAME OVER define boundaries. The policy gets screen data—not parsed game-state features.

Project evidence: GOALS.md · rl/env.py · rl/model.py · rl/evaluate.py02 / 10

“No oracle” means no expert action provider, hidden-state observation, or search over future moves. It does not mean no engineering: humans and the coding agent chose algorithms, debugged screen parsing, and compared validation results.

The training curriculum can save and restore opaque emulator snapshots of states reached by the learner itself. That reset mechanism is not an input to the neural network and does not choose controls. Evaluation always starts from boot.

02 / Perception & actionOne compact convolutional network

Four screens turn an image into motion.

The network must infer what is moving. Nobody labels “ball,” “paddle,” or “good move.”

Screen-only, not literal RGB

Each 1 KiB screen becomes graphics pixels plus a fixed visible-ASCII code channel.

A short visual memory

Offsets −6, −4, −2, 0 actions. Each action advances 50,000 Z80 T-states.

The policy controls serving, too

None, left, right, space, left+space, right+space. No automatic SPACE override.

Actual winning-checkpoint architecture and timing: rl/model.py · models/breakdown-all-eight/state.json03 / 10

The screen is 64×16 character cells. Each cell maps to a 2×3 graphics block and a second channel encoding visible ASCII as a normalized character code. Four screens therefore give eight channels at 128×48 resolution. This is structured video-memory encoding, not camera pixels, and is an important difference from DQN.

The four thumbnails are real frames near action 1800, not a hypothetical motion diagram. In PPO mode, the inherited advantage head supplies policy logits and the value head supplies a baseline; it is not selecting actions by Q-value argmax.

Winning config: state.json · PPO implementation: rl/ppo.py · Schulman et al., PPO (2017)05 / 10

The selected learner used 32 CPU-only emulator workers, reserving half for full from-boot games. The other half could restore training-only Level-8 states it discovered itself. This prevents later-stage practice from replacing all early-game experience.

GAE uses gamma approximately 0.99750 and lambda approximately 0.97468. Life loss may end a training return, but never forces a serve; evaluation runs complete games. Adam and gradient clipping are used. The final learner is PPO with auxiliary self-imitation and self-reference terms, not plain PPO alone.

05 / More learning from rare experiencesTraining-only aids ≠ an action oracle

Practice it. Replay it. Don’t forget it.

The extra supervision came from the agent’s own past—not a better player.

01 · Self-generated curriculum

Revisit hard situations

Save opaque states reached during live training. Restore them on later resets to practice rare late-game situations.

No hand-authored states. No test/replay imports. Hidden state is restored, not exposed to the policy.

02 · Self-imitation learning

Reuse good decisions

Replay its own completed experience. Reinforce an action when its observed return exceeds the value estimate.

Four auxiliary updates per rollout. Bounded buffer; truncated segments are discarded. No demonstrations.

03 · Own-policy reference

Retain learned behavior

An older 32M-action checkpoint supplies a soft reference distribution on the learner’s current screens.

Training-only weight 0.1. Never chooses a live action. No reference model is needed at inference.

rl/curriculum.py · rl/sil.py · rl/reference.py · SIL paper · Kickstarting inspiration06 / 10

These are deliberate training advantages relative to vanilla DQN; “no oracle” should not hide them. Curriculum snapshots contain emulator state for reset, but only four video-memory frames enter the policy. Half the workers remain from-boot. Only new score earned after a restore is rewarded.

The self-reference term is a custom fixed-weight KL penalty inspired by kickstarting, using this agent's own earlier RL checkpoint—not an external expert. Self-imitation is also an adaptation. The experiment history does not establish that each addition independently caused the final victory.

The exact original game uses GAME OVER for both losing and winning. Its final-level branch increments an internal level counter but jumps to termination before updating the displayed level. A spare ball on this terminal Level-8 screen is sufficient proof of victory.

Static code inspection was used to validate this interpretation; no live CPU state or non-video memory was fed to the policy or win detector. A last-ball Level-8 ending is ambiguous, so reported verified win rates are lower bounds. Score alone does not prove victory: falling bricks and permanent obstacles complicate a score threshold.

The familiar Breakout demonstration was Atari 2600, not Commodore Amiga. This comparison uses the 2015 Nature recipe; the earlier 2013 paper covered seven games. “49 games” does not mean one jointly trained multitask model: each game had separate training under the shared recipe.

We should not claim a direct reproduction or algorithmic superiority. Observation encoding, game dynamics, timing, training starts and evaluation protocols differ. Our early Double DQN, dueling and prioritized replay choices are later DQN-family extensions, not all features of the original paper.
